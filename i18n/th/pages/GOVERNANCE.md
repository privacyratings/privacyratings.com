# ธรรมาภิบาล

วิธีการตัดสินใจ วิธีเลือกตัวเลือกแนะนำ และวิธีจัดการผลประโยชน์ทับซ้อน

## ผู้ดูแล

ผู้ดูแลตรวจทานและรวม pull request คัดแยก issue และดูแล Discussions รายชื่อผู้ดูแลอยู่ใน [`.github/CODEOWNERS`](.github/CODEOWNERS) ทุกคนสามารถเป็นผู้ดูแลได้หลังจากมีประวัติการมีส่วนร่วมที่ถูกต้องและมีแหล่งอ้างอิงที่ดี

## การยอมรับการเปลี่ยนแปลง

1. การเปลี่ยนแปลงทั้งหมดต้องผ่าน pull request ไม่มีใคร รวมถึงผู้ดูแล push การเปลี่ยนแปลงผลการประเมินไปยัง `main` โดยตรง
2. ทุก pull request ต้องผ่าน `npm test` (การตรวจสอบความถูกต้องและการบิลด์)
3. ผู้ดูแลอย่างน้อยหนึ่งคนต้องอนุมัติ pull request
4. คำตอบต้องมีหลักฐานจากแหล่งข้อมูลปฐมภูมิ: เอกสารทางการ ซอร์สโค้ด ไฟล์สัญญาอนุญาต รายงานการตรวจสอบที่เผยแพร่ หรือการทดสอบที่ทำซ้ำได้ บทวิจารณ์ บล็อกโพสต์ และคำกล่าวอ้างทางการตลาดที่ไม่มีรายละเอียดไม่ถือเป็นหลักฐาน
5. เมื่อแหล่งข้อมูลขัดแย้งกัน ให้ถือแหล่งข้อมูลปฐมภูมิที่ใหม่ที่สุด หากยังไม่ชัดเจน คำตอบคือ "ไม่ทราบ"

## การเปลี่ยนแปลงเกณฑ์

เกณฑ์เป็นตัวกำหนดทุกคะแนน การเปลี่ยนแปลงใน `criteria/` จึงต้องระมัดระวังมากขึ้น:

- เปิด issue "Criteria change" หรือ Discussion ก่อน
- pull request ต้องเปิดไว้อย่างน้อย 7 วันเพื่อรับความคิดเห็นจากสาธารณะ
- ต้องได้รับการอนุมัติจากผู้ดูแลสองคน
- id ของเกณฑ์จะไม่ถูกเปลี่ยนชื่อหลังจากเผยแพร่แล้ว การยกเลิกเกณฑ์ทำได้โดยลบออกใน pull request ที่อธิบายเหตุผล

## ตัวเลือกแนะนำ

- แต่ละหมวดหมู่มีตัวเลือกแนะนำได้ไม่เกินสองรายการ
- ตัวเลือกแนะนำต้องมี `pick_reason` ที่อธิบายการเลือกด้วยภาษาที่เข้าใจง่าย
- แต่ละหมวดหมู่มีตัวเลือกแนะนำไม่เกินสองรายการ เรียงลำดับด้วย `pick: 1` และ `pick: 2`
- ตัวเลือกแนะนำมาจากกองบรรณาธิการ แสดงแยกต่างหากและไม่มีผลต่อคะแนน
- ทุกคนสามารถโต้แย้งตัวเลือกแนะนำได้ในหมวด "Picks" ของ Discussions การโต้แย้งจะได้รับคำตอบอย่างเปิดเผย

## ผลประโยชน์ทับซ้อน

Privacy Ratings ดูแลโดยทีมที่อยู่เบื้องหลัง Forward Email รายการที่เกี่ยวข้องกับผู้ดูแลเรียกว่า "รายการที่เกี่ยวข้อง" ปัจจุบันหมายถึง Forward Email

กฎสำหรับรายการที่เกี่ยวข้อง:

- รายการที่เกี่ยวข้องแต่ละรายการมี `disclosure` แสดงไว้ที่ด้านบนของหน้า
- pull request ที่เพิ่มคะแนนของรายการที่เกี่ยวข้อง หรือทำให้เป็นตัวเลือกแนะนำ ต้องลิงก์หลักฐานสำหรับทุกคำตอบที่เปลี่ยนแปลง และต้องเปิดไว้อย่างน้อย 7 วันก่อนรวม
- pull request ที่ลดคะแนนของรายการที่เกี่ยวข้องโดยมีหลักฐานที่ถูกต้องจะถูกรวมเหมือน pull request อื่นๆ
- ผู้ดูแลต้องเพิ่มการเปิดเผยข้อมูลในรายการใดๆ ที่ตนเองหรือนายจ้างมีความเกี่ยวข้องทางการเงินหรือส่วนตัว

## เงิน

- ไม่มีลิงก์แอฟฟิลิเอต การตรวจสอบความถูกต้องจะปฏิเสธ URL ที่มีพารามิเตอร์การแนะนำหรือการติดตาม
- ไม่มีการจ่ายเงินเพื่อจัดอันดับ รายการที่ได้รับการสนับสนุน หรือบทวิจารณ์แบบจ่ายเงิน
- ผู้ให้บริการสามารถส่งการแก้ไขได้เหมือนคนอื่นๆ พร้อมหลักฐาน และต้องแจ้งว่าตนเป็นผู้ให้บริการ

## การดูแลชุมชน

issue, pull request และ Discussions ต้องปฏิบัติตาม[หลักจรรยาบรรณ](CODE_OF_CONDUCT.md) ผู้ดูแลอาจล็อกหรือซ่อนความคิดเห็นที่หยาบคาย นอกประเด็น หรือเป็นการโฆษณา
