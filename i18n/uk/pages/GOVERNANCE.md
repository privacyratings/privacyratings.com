# Управління

Як ухвалюються рішення, як обирається наш вибір і як розв’язуються конфлікти інтересів.

## Супровідники

Супровідники перевіряють і зливають pull request, сортують issues і модерують Discussions. Супровідників перелічено у [`.github/CODEOWNERS`](.github/CODEOWNERS). Будь-хто може стати супровідником, маючи історію точних внесків із добрими джерелами.

## Як приймаються зміни

1. Усі зміни проходять через pull request. Ніхто, зокрема супровідники, не надсилає зміни рейтингів безпосередньо в `main`.
2. Кожен pull request має пройти `npm test` (перевірку та збирання).
3. Щонайменше один супровідник схвалює pull request.
4. Відповіді потребують доказів із першоджерела: офіційної документації, вихідного коду, файлів ліцензій, опублікованих звітів аудитів або відтворюваних тестів. Огляди, дописи в блогах і маркетингові заяви без подробиць не є доказами.
5. Коли джерела суперечать одне одному, перевагу має найновіше першоджерело. Якщо й тоді незрозуміло, відповідь — «невідомо».

## Зміни критеріїв

Критерії визначають кожен бал, тому зміни в `criteria/` потребують більшої уваги:

- Спочатку створіть issue «Criteria change» або обговорення в Discussions.
- Pull request залишається відкритим щонайменше 7 днів для публічних коментарів.
- Він потребує схвалення двох супровідників.
- Ідентифікатори критеріїв ніколи не перейменовуються після публікації. Щоб вивести критерій з ужитку, видаліть його в pull request із поясненням причини.

## Наш вибір

- Кожна категорія може мати до двох варіантів нашого вибору.
- Вибір повинен мати `pick_reason`, що пояснює його простими словами.
- Кожна категорія має щонайбільше два варіанти вибору, упорядковані за допомогою `pick: 1` і `pick: 2`.
- Вибір — редакційний. Він показується окремо й ніколи не змінює балів.
- Будь-хто може оскаржити вибір у категорії «Picks» у Discussions. На оскарження відповідають публічно.

## Конфлікти інтересів

Privacy Ratings супроводжує команда Forward Email. Записи, пов’язані із супровідниками, є «пов’язаними записами». Зараз це Forward Email.

Правила для пов’язаних записів:

- Кожен пов’язаний запис містить `disclosure`, що показується вгорі його сторінки.
- Pull request, що підвищує бал пов’язаного запису або робить його нашим вибором, має містити посилання на докази для кожної зміненої відповіді й залишатися відкритим щонайменше 7 днів до злиття.
- Pull request, що знижує бал пов’язаного запису з обґрунтованими доказами, зливається як будь-який інший.
- Супровідники повинні додавати розкриття інформації до будь-якого запису, з яким вони чи їхній роботодавець мають фінансовий або особистий зв’язок.

## Гроші

- Жодних партнерських посилань. Перевірка відхиляє URL із реферальними параметрами чи параметрами стеження.
- Жодних платних розміщень, спонсорованих записів чи платних оглядів.
- Постачальники можуть надсилати виправлення, як і будь-хто інший, з доказами, і мають зазначати, що вони є постачальником.

## Модерація

Issues, pull request і Discussions підпадають під дію [Кодексу поведінки](CODE_OF_CONDUCT.md). Супровідники можуть блокувати або приховувати коментарі, що є образливими, не стосуються теми або мають рекламний характер.
