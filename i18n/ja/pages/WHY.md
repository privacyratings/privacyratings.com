# Privacy Ratings が存在する理由

プライバシーガイドは、何百万人もの人がより良いアプリやサービスを選ぶ助けになっています。優れた仕事をしているものも多くあります。しかし、その多くには共通の弱点があります。

- **ルールが不明確。** あるサービスが掲載されたり外されたりしても、その理由はフォーラムのスレッドや非公開の議論の中にあるか、まったく公開されていません。
- **合格か不合格かだけ。** リストは「おすすめ」と書くか、何も書かないかのどちらかです。どこまで基準に近かったのか、何が変われば結果が変わるのかは示されません。
- **確認のない主張。** 説明には「暗号化」や「ノーログ」と書かれていても、読者が確認できるものへのリンクがありません。
- **テストがない。** ホスト型サービスについて、TLS 設定、セキュリティヘッダー、メール認証などの基本的なセキュリティが確認されることはほとんどありません。
- **プラットフォームが別。** 提案や議論は、実際のコンテンツとは別に、専用のアカウントとモデレーションが必要なフォーラムやチャットサーバーで行われます。
- **変化が遅い。** 製品が変わっても、更新が少数の人に依存しているため、リストは古いままになりがちです。

Privacy Ratings は、これらの一つひとつを解決するために作られています。

## awesome リストから、継続的に保守されるリソースへ

こうしたガイドの多くは GitHub のリストとして始まりました。[Sindre Sorhus](https://github.com/sindresorhus/awesome) が始めた「awesome」リストの形式により、誰でも厳選リストを簡単に公開できるようになり、何千もの awesome-something リストが続きました。その多くは互いのフォークです。[Awesome Privacy](https://github.com/lissy93/awesome-privacy) のようなリストは価値ある仕事をしており、ここにある多くの項目も最初はそこに掲載されていました。

この形式には弱点があります。ほとんどのリストは1人か2人のボランティアに依存しています。メンテナーが離れると、リストは更新されなくなるか、アーカイブされるか、それぞれが古くなっていくフォークに分かれてしまいます。読者はどのコピーが最新なのかわからず、リストの中身がテストや採点されることもありません。

**Privacy Ratings は、企業である [Forward Email](https://forwardemail.net) が支援・運営しています。** 離れたりリポジトリをアーカイブしたりするかもしれないボランティアに依存していません。データは単一の README ではなく構造化されているため、毎日自動で検証、採点、テストできます。そして、すべてがオープンソースで CC BY-SA ライセンスのため、コミュニティはいつでもコピーし、確認し、改善できます。

## 何が違うのか

**すべてのルールが公開されています。** 各カテゴリには、1〜3の重みが付いた短い質問のリストがあります。質問、各回答の意味、その確認方法は、すべて [`criteria/`](criteria/) フォルダーにあります。[評価基準](https://privacyratings.com/criteria/)をご覧ください。

**すべての回答に根拠があります。** 「はい」または「一部」には、ドキュメント、ソースコード、ライセンスファイル、監査報告書など、誰でも確認できる出典へのリンクが必要です。根拠のないものは「不明」とみなされ、0点になります。項目にグレードが付くのは、十分な数の回答が根拠に裏付けられている場合だけです。

**リストだけでなくスコア。** すべての項目に0〜100のスコアが付くため、読者はサービス同士を比較し、それぞれがどこで足りないのかを正確に確認できます。

**自動セキュリティテスト。** ホスト型サービスは、Qualys SSL Labs、Mozilla HTTP Observatory、Internet.nl（メールプロバイダーには Internet.nl のメールテストを含む）で定期的にテストされます。結果はリポジトリに保存され、各ページからリンクされています。[SCANS.md](SCANS.md) をご覧ください。

**管轄を公開。** すべてのページに、企業の拠点、その国がファイブ・アイズ、ナイン・アイズ、フォーティーン・アイズに含まれるかどうか、GDPR が適用されるかどうか、米国 CLOUD Act が及ぶかどうかが表示されます。プロバイダーが提出できる内容は主に何を保持しているか、誰が鍵を持っているかによって決まるため、管轄は表示しますが採点はしません。[管轄](https://privacyratings.com/jurisdictions/)と[CLOUD Act](https://privacyratings.com/cloud-act/)をご覧ください。

**すべては GitHub で行われます。** 提案と修正は GitHub の Issue です。変更はプルリクエストです。議論は GitHub Discussions で行われます。別のフォーラム、チャットサーバー、アカウントシステムはありません。すべての評価へのすべての変更に公開の履歴があります。

**オープンデータ。** 評価はプレーンな Markdown と YAML のファイルで、データ全体が JSON として公開されています。コンテンツは CC BY-SA 4.0 ライセンスのため、誰でも再利用できます。

**おすすめはおすすめとして明示。** メンテナーはカテゴリごとに1つか2つのおすすめを選び、それぞれの理由を説明します。おすすめは別に表示され、スコアを変えることはないため、読者は編集上の判断と測定された結果をいつでも区別できます。

## 誰が保守しているか

Privacy Ratings は、ここでも評価されているプライバシー重視のメールサービス [Forward Email](https://forwardemail.net) が支援、資金提供、保守しています。これによりプロジェクトは長期的に保守されますが、同時に利益相反でもあるため、公開の場で扱っています。

- Forward Email は、他のすべてのメールプロバイダーと同じ評価基準で採点されます。
- その項目には開示が付いており、メンテナーと別のつながりがある項目にも同様に開示が付きます。
- 関係のある項目のスコアを上げる変更は、根拠へのリンクが必要で、マージ前に公開レビューのために一定期間オープンにしておく必要があります。[GOVERNANCE.md](GOVERNANCE.md) をご覧ください。
- アフィリエイトリンク、有料掲載、スポンサーシップはありません。検証により、紹介パラメーター付きのリンクは拒否されます。

評価が間違っていると思ったら、根拠を添えて Issue またはプルリクエストを作成してください。プロセスはそれだけです。
