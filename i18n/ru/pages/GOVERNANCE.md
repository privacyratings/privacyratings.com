# Управление

Как принимаются решения, как делается выбор и как разрешаются конфликты интересов.

## Сопровождающие

Сопровождающие проверяют и принимают pull request, разбирают issues и модерируют Discussions. Сопровождающие перечислены в [`.github/CODEOWNERS`](.github/CODEOWNERS). Любой может стать сопровождающим, если у него есть история точных вкладов с надёжными источниками.

## Как принимаются изменения

1. Все изменения проходят через pull request. Никто, включая сопровождающих, не отправляет изменения рейтингов напрямую в `main`.
2. Каждый pull request должен проходить `npm test` (проверка и сборка).
3. Pull request одобряет как минимум один сопровождающий.
4. Ответам нужны подтверждения из первоисточника: официальная документация, исходный код, файлы лицензий, опубликованные отчёты об аудите или воспроизводимые тесты. Обзоры, записи в блогах и маркетинговые заявления без подробностей подтверждениями не являются.
5. Если источники расходятся, приоритет у самого свежего первоисточника. Если ясности по-прежнему нет, ответ — «неизвестно».

## Изменения критериев

Критерии определяют каждый балл, поэтому изменения в `criteria/` требуют большей осторожности:

- Сначала откройте issue «Criteria change» или Discussion.
- Pull request остаётся открытым для публичных комментариев не менее 7 дней.
- Нужно одобрение двух сопровождающих.
- Идентификаторы критериев после публикации никогда не переименовываются. Чтобы вывести критерий из использования, удалите его в pull request с объяснением причин.

## Наш выбор

- В каждой категории может быть до двух выборов.
- У выбора должно быть поле `pick_reason`, простым языком объясняющее решение.
- В каждой категории не более двух выборов, упорядоченных с помощью `pick: 1` и `pick: 2`.
- Выбор редакционный. Он показывается отдельно и никогда не меняет баллы.
- Любой может оспорить выбор в категории Discussions «Picks». На возражения отвечают публично.

## Конфликты интересов

Privacy Ratings сопровождается командой Forward Email. Записи, связанные с сопровождающими, называются «аффилированными записями». Сейчас это Forward Email.

Правила для аффилированных записей:

- Каждая аффилированная запись содержит поле `disclosure`, которое показывается вверху её страницы.
- Pull request, который повышает баллы аффилированной записи или делает её выбором, должен ссылаться на подтверждения для каждого изменённого ответа и оставаться открытым не менее 7 дней до принятия.
- Pull request, который понижает баллы аффилированной записи на основании обоснованных подтверждений, принимается как любой другой.
- Сопровождающие обязаны добавить раскрытие информации к любой записи, с которой они или их работодатель имеют финансовую или личную связь.

## Деньги

- Никаких партнёрских ссылок. Проверка отклоняет URL с реферальными параметрами или параметрами отслеживания.
- Никаких платных размещений, спонсорских записей или платных обзоров.
- Производители могут отправлять исправления, как и все остальные, с подтверждениями, и обязаны сообщить, что они производитель.

## Модерация

Issues, pull request и Discussions подчиняются [Кодексу поведения](CODE_OF_CONDUCT.md). Сопровождающие могут блокировать или скрывать оскорбительные, не относящиеся к теме или рекламные комментарии.
